# Coherence Log

**Version 1.7. June 2026. Living document. Updated continuously.**

This log captures insights, refinements, and new axioms that surface during sessions and might apply to earlier work. Entries are not acted on immediately. Forward work continues. Integration passes are run periodically — when the log has accumulated enough, when a phase is about to mature, or when the founder calls for one — to evaluate each entry and update earlier files where the entry genuinely improves the work.

The mechanism preserves forward motion while keeping a channel open for upgrade. The book that ships at the end of the project reflects every refinement and every axiom arrived at across the entire build.

This log is one of four intake channels defined in `16_PROTOCOL.md`: the Coherence Log (this file), the Rigor Map (`18_RIGOR_MAP.md`), the Resource Protocol (`19_RESOURCE_PROTOCOL.md` and `RESOURCE_CATALOG.md`), and the Book-Field Revision Mechanism (defined in `16_PROTOCOL.md`).

---

## How to use this file

Entries are added during or between sessions. Each entry has the same shape:

**[Date]** *Class: Recognition / Discipline / Specifics.* — [What surfaced.] [Where it might apply.]

Each entry is classified by class:

- **Recognition.** What the work transmits. Refinements at this layer are rare and must be carefully tested before integration.
- **Discipline.** How the work moves. Refinements at this layer are occasional, after the new frame proves itself in practice.
- **Specifics.** What gets built and when. Refinements at this layer are continuous.

When an integration pass is run, entries are reviewed in order. For each entry: evaluate whether it improves the earlier work, decide where it lands, make the change in the relevant file, mark the log entry as integrated with a brief note about how it was handled.

When an existing file is updated through an integration pass, a brief note at the bottom of that file records what was upgraded and when.
